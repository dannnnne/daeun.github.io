# A First Look at Model Supply Chain: From the Risk Perspective

## Abstract

* Hugging Face와 같은 플랫폼에서 공개 AI 모델이 빠르게 확산되면서 복잡한 **Model Supply Chain**이 형성되고 있음.
* 하나의 Base Model은 다양한 transformation operation을 통해 지속적으로 파생됨.

  * Fine-tuning
  * Quantization
  * Merging
  * Adapter
* 이러한 과정에서 새로운 Derived Model이 생성되고 모델 간 dependency relation이 형성됨.
* 하지만 공개 모델의 **provenance, dependency, quality, risk propagation**을 공급망 관점에서 대규모로 분석한 연구는 부족함.
* 본 연구는 Hugging Face의 모델 및 dependency relation을 수집하여 Model Supply Chain을 구축하고 다음 네 가지 관점에서 분석함.

  * Usage
  * Evolution
  * Quality
  * Risk

---

# Introduction

## Background

공개 AI 모델의 확산으로 모델을 처음부터 개발하기보다 기존 모델을 재사용하는 경우가 많아짐.

하나의 모델에 Fine-tuning, Quantization, Merging 등의 **transformation operation**을 수행하면 새로운 모델이 만들어지며, 두 모델 사이에는 dependency relation이 형성됨.

* **Base Model**: transformation의 기반이 되는 upstream model
* **Derived Model**: Base Model을 변형하여 생성된 downstream model

예를 들어,

```text
Model A
  ↓ Fine-tuning
Model B
  ↓ Quantization
Model C
```

와 같은 구조가 형성될 수 있음.

기존 소프트웨어의 dependency는 보통 특정 버전의 library를 import하여 사용하는 형태인 반면, AI model supply chain에서는 upstream model의 parameter나 architecture를 이용하여 **새로운 model artifact를 생성한다는 특징**이 있음.

---

## Problem

AI 개발자는 생산성을 높이기 위해 기존 모델의 architecture와 parameter를 적극적으로 재사용함.

그 결과 Model Supply Chain이 빠르게 복잡해지고 있지만 현재는 다음과 같은 문제가 존재함.

* 어떤 모델이 어떤 모델로부터 파생되었는지 충분히 기록되지 않음.
* Model Supply Chain의 실제 구조에 대한 이해가 부족함.
* 모델의 추가·삭제·업데이트가 공급망에 미치는 영향이 충분히 알려져 있지 않음.
* Model Card의 dependency, dataset 등의 정보가 얼마나 정확한지 명확하지 않음.
* upstream model의 위험이 downstream model로 어떻게 전파되는지 충분히 연구되지 않음.

---

## Limitations of Previous Work

기존 연구에서도 공개 모델을 분석했지만 다음과 같은 한계가 존재함.

1. 공개 모델 자체의 특징을 분석하는 데 집중하여 **Model Supply Chain 관점의 분석이 부족함**.
2. 분석 규모와 범위가 제한되어 실제 공개 모델 생태계의 공급망을 충분히 반영하지 못함.
3. 다음 요소들을 통합적으로 분석한 연구가 부족함.

   * Usage
   * Evolution
   * Quality
   * Risk

# Model Supply Chain Construction

## Target Platform

분석 대상은 **Hugging Face**임.

연구팀은 Hugging Face의 Model Card metadata를 크롤링하여 전체 모델 집합을 구축함.

---

## Dependency Extraction

Model Card metadata를 parsing하여 dependency relation을 추출함.

분석하는 transformation operation은 다음과 같음.

* Fine-tune
* Adapter
* Quantize
* Merge

Adapter는 Fine-tuning의 한 종류로 취급함.

---

## Dependency Relation

하나의 dependency relation을 다음의 3-tuple로 정의함.

```text
d = <m_b, m_d, op>
```

* `m_b`: Base Model
* `m_d`: Derived Model
* `op`: transformation operation

즉,

```text
Base Model --operation--> Derived Model
```

의 관계를 하나의 dependency relation으로 표현함.

---

# RQ1. Usage Analysis

RQ1에서는 Model Supply Chain을 다음 세 가지 level에서 분석함.

1. Dependency Relation
2. Dependency Chain
3. Dependency Cluster

---

## Dependency Relation

### 주요 집합

* `M_b`: Base Model 집합
* `M_d`: Derived Model 집합
* `M_r = M_b ∪ M_d`: dependency relation에 참여하는 relational model
* `M_i`: dependency가 없는 isolated model
* `M_f`: Fine-tuning으로 생성된 모델
* `M_m`: Merging으로 생성된 모델
* `M_q`: Quantization으로 생성된 모델

Degree는 다음과 같이 정의함.

* `deg_in(m)`: 모델 `m`이 의존하는 upstream model의 수
* `deg_out(m)`: 모델 `m`을 기반으로 만들어진 downstream model의 수

---

### Overview of Models

전체 모델 중 약 **68.9%가 isolated model**임.

즉 Hugging Face metadata상 다른 모델과 dependency relation이 없는 모델이 전체의 약 2/3를 차지함.

하지만 나머지 약 31%의 relational model이 전체 다운로드의 약 **88%**를 차지함.

따라서,

> dependency relation을 가지는 모델의 수는 상대적으로 적지만 실제 모델 사용량에서는 매우 큰 비중을 차지함.

---

### Overview of Dependency Relations

Derived Model 중 Fine-tuning을 통해 만들어진 모델이 가장 많음.

* Fine-tuning: 약 79%
* Quantization: 약 18.6%
* Merging: 약 2.4%

Transformation type별 task를 분석한 결과:

* Fine-tuning
* Merging
* Quantization

모두 NLP task가 가장 큰 비중을 차지함.

---

### Top Model Analysis

In-degree와 Out-degree가 높은 모델 Top 10을 분석함.

대부분 NLP 관련 모델이었으며, 이는 **공개 모델 재사용 생태계에서 NLP 모델이 지배적인 위치를 가지고 있음**을 보여줌.

---

# Dependency Chain

## Definition

Dependency Chain은 Base Model에서 Derived Model로 이어지는 **연속적인 dependency relation의 경로**임.

예를 들어,

```text
Model A
  ↓ Fine-tuning
Model B
  ↓ Quantization
Model C
```

라면 다음과 같은 dependency chain이 형성됨.

```text
A → B → C
```

---

## Overview

전체 Dependency Chain 수는 약:

**1,008,871개**

이며 이 중 약 **60.8%가 길이 2 이상**임.

즉 많은 모델이 하나의 Base Model에서 직접 만들어지는 것이 아니라 여러 transformation 단계를 거쳐 생성됨.

---

## Operations in Dependency Chains

각 dependency chain에서 다음을 조사함.

* 어떤 operation이 등장하는가?
* 하나의 chain에 몇 개의 operation이 존재하는가?
* Fine-tuning, Quantization, Merging이 어떠한 조합으로 사용되는가?

전체적으로 Fine-tuning의 비율이 가장 높았음.

---

## Top Dependency Chain Analysis

가장 긴 dependency chain을 분석한 결과:

* Fine-tuning operation의 비율이 높음.
* 긴 chain의 대부분 역시 NLP model과 관련되어 있음.

---

# Dependency Cluster

## Definition

Dependency Cluster는 **동일한 root Base Model에서 시작하는 모든 dependency chain을 하나로 묶은 것**임.

예를 들어,

```text
        A
      /   \
     B     C
     |    / \
     D   E   F
```

가 존재한다면 A를 root로 하는 전체 구조가 하나의 Dependency Cluster가 됨.

즉 하나의 Base Model에서 파생된 전체 **model supply tree**라고 볼 수 있음.

---

## Findings

대부분의 cluster는 크기가 작음.

* 5개 이하의 모델을 포함한 cluster가 다수 존재함.

전체 cluster의 operation 구성을 살펴보면 Quantization 관련 cluster가 상당한 비중을 차지함.

하지만 규모가 가장 큰 Top 10 Cluster에서는:

* Fine-tuning이 우세함.
* 대부분 NLP task와 관련됨.

---

# RQ2. Evolution Analysis

Model Supply Chain의 시간에 따른 변화를 분석하기 위해 **매주 수요일마다 총 7주간 snapshot**을 수집함.

---

## Addition and Deletion of Models

### Addition

총 약 **27,311개의 모델**이 추가됨.

그중:

* 19,687개: isolated model
* 나머지: relational model

새롭게 추가된 relational model 대부분은 Derived Model이었음.

또한 새 Derived Model을 생성하는 transformation 역시 Fine-tuning이 가장 많았음.

---

### Deletion

총 약 **6,190개의 모델**이 삭제됨.

이 중:

* 1,823개: relational model

삭제된 relational model 역시 대부분 Derived Model이었으며 Fine-tuning 기반 모델이 가장 큰 비중을 차지함.

---

# Addition and Deletion of Chains and Clusters

## Addition

새롭게 추가된 relational model 중:

* 약 7,082개가 기존 dependency chain에 추가됨.
* 538개의 새로운 chain이 생성됨.
* 191개의 새로운 cluster가 생성됨.

즉 새로운 relational model은 새로운 공급망을 생성하기보다는 **기존 Model Supply Chain을 확장하는 형태로 추가되는 경우가 많음**.

---

## Deletion

삭제 과정에서:

* 32개의 chain이 완전히 삭제됨.
* 26개의 cluster가 완전히 삭제됨.
* 127개의 Base Model이 삭제됨.
* 299개의 Derived Model이 삭제됨.

특히 Base Model의 삭제는 큰 영향을 미침.

Base Model 삭제로 인해:

* 1,440개의 chain
* 78개의 cluster

가 영향을 받음.

즉,

> upstream Base Model의 안정성이 전체 downstream supply chain의 안정성과 직결될 수 있음.

---

# Changes of Top Chains and Clusters

가장 큰 cluster들의 구성은 비교적 안정적으로 유지됨.

그러나 cluster의 순위는 지속적으로 변경됨.

주요 이유:

* Cluster마다 성장 속도가 다름.
* 새로운 인기 모델이 등장함.
* 기존 Base Model에서 새로운 Derived Model이 계속 생성됨.

---

# Update Analysis

단순한 Model Card 수정은 실제 Model Update로 간주하지 않음.

실제 모델 artifact에 변화가 있는 경우를 Update로 판단함.

총:

**145,445개의 Model Update**

가 확인됨.

그중 relational model은:

**46,277개**

였음.

세부적으로:

* Base Model: 13,666개
* Derived Model: 37,685개
* Fine-tuning Derived Model: 30,872개

하지만 실제 모델이 변경되었음에도 Model Card metadata나 version 관련 정보를 함께 수정하는 경우는 매우 적었음.

즉,

> 실제 모델 artifact의 변경 이력과 Model Card의 provenance 정보가 제대로 동기화되지 않는 문제가 존재함.

# Quality Analysis of Models

각 field의 Missing Rate는 다음과 같음.

| Field           | Missing Rate |
| --------------- | -----------: |
| License         |        28.3% |
| Performance     |        82.8% |
| Prompt Template |        33.8% |
| Dataset         |        76.8% |

특히 Performance와 Dataset 정보의 누락률이 매우 높음.

즉 어떤 Dataset을 사용하여 Fine-tuning했는지 추적하기 어려운 모델이 많음.

# Quality Analysis of Dependency Relations

Dependency Relation의 정확성을 평가하기 위해 Precision과 Recall을 측정함.

## Dependency가 선언되지 않은 모델

201개의 모델은 dependency를 선언하지 않음.

하지만 이 중 **79개는 실제로 다른 모델로부터 파생된 모델**이었음.

따라서 Recall은:

**68.5%**

로 나타남.

---

## Dependency가 선언된 모델

177개의 모델은 dependency relation을 선언함.

이 중 대부분은 정확했으나 5개의 dependency가 잘못되어 있었음.

따라서 Precision은:

**97.2%**

로 높게 나타남.

정리하면,

> **기록되어 있는 dependency는 대부분 정확하지만, 실제 dependency가 있음에도 기록되지 않은 경우가 많음.**

---

## 원인

논문에서는 크게 두 가지 원인을 제시함.

1. 개발자가 dependency field를 작성하지 않거나 간과함.
2. Hugging Face metadata schema가 일부 transformation operation을 충분히 표현하지 못함.

378개의 분석 모델 중 **363개가 최소 하나 이상의 field에서 정보가 누락되거나 부정확했음**.

# Hallucination Rate Evaluation

Hallucination 평가에는 **HHEM-2.1-Open**을 사용함.

Dataset:

* CNN/DailyMail corpus

모델의 출력이 원문의 내용을 충실하게 반영하는지 또는 hallucination을 포함하는지를 평가함.

값이 높을수록 Hallucination 위험이 큰 것으로 해석함.

---

# Jailbreak Success Rate Evaluation

Jailbreak 평가에는 **AdvBench**를 사용함.

AdvBench에는 폭력, 사이버 범죄 등 다양한 harmful behavior를 요구하는 adversarial test case가 포함되어 있음.

각 test case를 모델에 입력한 뒤:

* 모델이 요청을 거부하는지
* Jailbreak되어 harmful response를 생성하는지

를 확인함.

이를 이용하여 **Jailbreak Success Rate(JSR)**를 계산함.

JSR이 높을수록 Jailbreak Risk가 큼.

---

# Prompt Injection Success Rate Evaluation

Prompt Injection 평가에는 다양한 injection scenario를 포함하는 약 **4,900개의 test case**를 사용함.

각 test case에서 Prompt Injection 성공 여부를 판단하여:

**Prompt Injection Success Rate(PSR)**

를 측정함.

PSR이 높을수록 Prompt Injection 공격에 취약함.

---

# Risk Analysis of Fine-tuning

다운로드 수를 기준으로 Fine-tuning dependency relation 중 Top 100을 선정함.

Prompt Template이 존재하지 않아 평가하기 어려운 relation을 제외한 결과:

**75개의 Fine-tuning relation**

을 분석함.

Fine-tuning operation은 세 가지로 분류함.

---

## Supervised Fine-Tuning (SFT)

일반적으로 모델 parameter 전반을 수정하는 Fine-tuning.

* 19 relations

---

## Parameter-Efficient Fine-Tuning (PEFT)

전체 parameter가 아니라 일부 parameter 또는 별도의 작은 parameter만 학습하는 방식.

* 16 relations

---

## Others

SFT 또는 PEFT로 명확히 분류되지 않는 Fine-tuning.

* 40 relations

---

## Analysis

각 relation에 대해 다음과 같이 위험 변화를 측정함.

```text
Δ Risk = Risk(Derived Model) - Risk(Base Model)
```

---

## SFT

SFT는 Base Model과 비교했을 때 risk profile의 변화가 상대적으로 크게 나타남.

Q2 기준:

* HR 감소
* JSR 감소
* PSR 증가

즉 각 위험의 방향은 다르지만 **Base Model의 risk profile을 상대적으로 크게 변화시키는 경향**이 있음.

---

## PEFT

PEFT는 Base Model의 risk profile을 상대적으로 잘 유지함.

Q2 기준:

* HR 변화 거의 없음
* JSR 감소
* PSR 변화 거의 없음

다만 PSR에서는 일부 큰 outlier가 존재함.

---

## Others

* HR 변화가 상대적으로 작음
* JSR 감소
* PSR 증가

즉 Fine-tuning 방식에 따라 서로 다른 risk propagation pattern이 나타남.

---

# Risk Analysis of Quantization

Text Generation 관련 주요 Quantization Cluster 10개를 선택함.

Prompt Template이 존재하지 않는 cluster를 제외하고 최종적으로 **4개의 cluster**를 분석함.

각 모델에 대해:

* 8-bit
* 4-bit
* 2-bit

Quantization을 비교함.

---

## Findings

bit 수가 충분히 높은 경우에는 Base Model과 비교했을 때 risk 변화가 상대적으로 작음.

그러나 **bit 수가 작아질수록 risk profile 변화가 커지는 경향**이 나타남.

### Hallucination

bit 수가 작아질수록 Hallucination Risk가 증가함.

### Jailbreak / Prompt Injection

정리된 실험 결과에서는 bit 수가 작아질수록 JSR과 PSR이 감소하는 경향이 관찰됨.

즉 Quantization은 모든 위험을 단순히 증가시키거나 감소시키는 것이 아니라 **위험의 종류에 따라 서로 다른 영향을 줄 수 있음**.

---

# Risk Analysis of Merging

8개의 Merged Model을 선정하여 분석함.

Merged Model은 여러 Base Model을 결합하여 만들어지므로 직관적으로는 각 Base Model의 평균적인 risk를 가질 것이라고 예상할 수 있음.

하지만 실제 결과는 달랐음.

Merged Model의 risk는 Base Model들의 평균에 가까워지는 것이 아니라 **특정 Base Model의 risk extreme에 가까워지는 경향**이 나타남.

즉,

> **Model Merging 이후의 위험은 Base Model들의 단순 평균으로 예측하기 어려움.**

---

# Implications

전체 모델의 약 1/3만 dependency relation을 가지고 있지만 이러한 모델이 전체 다운로드의 약 88%를 차지함.

또한 Derived Model의 약 79%가 Fine-tuning으로 생성됨.

따라서 Model Supply Chain 관리는 실제 공개 AI 생태계에서 중요한 문제임.

---

## Upstream Model Maintainers

Base Model은 많은 downstream model에 영향을 줄 수 있으므로 높은 수준의 provenance 관리가 필요함.

필요한 요소:

* Model provenance 명확화
* Model BOM 유지
* Version 및 변경 이력 관리
* 지속적인 risk 평가
* 최신 risk 정보 제공

Base Model의 변경 또는 삭제가 많은 downstream model에 영향을 줄 수 있으므로 **upstream model의 transparency와 stability가 중요함**.

---

## Downstream Model Consumers

Model Consumer는 단순히 Model Card의 성능 정보만 확인해서는 안 됨.

다음 요소를 함께 고려해야 함.

* Model Performance
* Safety Risk
* Security Risk
* Base Model
* Dataset
* Transformation History

또한 새로운 Derived Model을 생성한다면 수행한 transformation operation과 dependency를 명확히 기록해야 함.

---

## Hugging Face Platform Designers

플랫폼 차원에서도 Model Supply Chain을 관리할 수 있는 기능이 필요함.

예:

* Model Version History
* Change History
* License Hash
* Base Model Checksum
* Performance Metadata
* Dependency Metadata
* Risk Evaluation
* Dependency Version Locking

---

## Model Supply Chain Researchers

향후 연구 방향으로 다음이 필요함.

### Dependency Relation Identification

Model Card에 기록되지 않은 dependency relation을 자동으로 탐지하는 기술.

### Standardized Metrics

Model Supply Chain의 품질과 위험을 평가할 표준화된 metric.

### Model Risk Database

각 모델의 safety/security risk를 저장하는 database.

### Risk Propagation Modeling

Base Model의 위험이:

* Fine-tuning
* Quantization
* Merging

등을 거쳐 downstream model로 어떻게 전달되는지 분석·예측하는 기술.

# Threats to Validity

## Incomplete Model Dependency

본 연구에서 Model Supply Chain은 주로 Hugging Face **Model Card metadata에 기록된 developer-provided dependency information**을 기반으로 구축함.

하지만 RQ3에서 확인했듯 실제 dependency가 존재하는데도 Model Card에 기록되지 않은 경우가 많음.

따라서 논문에서 구축한 Model Supply Chain이 실제 공급망의 모든 dependency relation을 포함한다고 보기는 어려움.

이는 향후 연구에서 중요한 문제로 볼 수 있음.

> **Model Card에 dependency가 존재하지 않을 때 실제 dependency relation을 어떻게 복원할 것인가?**

예를 들어 다음과 같은 정보들을 함께 활용하는 방향을 생각할 수 있음.

```text
Model Card
     +
Source Code
     +
Training Configuration
     +
Model Weight / Parameter Information
     +
Repository History
```

즉 metadata에만 의존하지 않는 **Model Supply Chain Provenance Recovery**가 향후 중요한 연구 방향이 될 수 있음.

---

## One-hop Risk Propagation Analysis

RQ4의 주요 분석은 다음과 같은 **single-hop dependency relation**에 집중함.

```text
Base Model → Derived Model
```

추가 분석에서는 multi-hop에서도 one-hop에서 관찰된 risk propagation pattern이 상당 부분 유지됨을 확인함.

하지만,

```text
A
↓ Fine-tuning
B
↓ Quantization
C
↓ Fine-tuning
D
```

처럼 여러 transformation을 거치면서 위험이 누적되는 **cumulative risk effect**는 충분히 분석하지 못함.

따라서 multi-hop Model Supply Chain에서 위험이 어떻게 누적·변형되는지는 추가적인 연구가 필요함.

---

# Conclusion

Hugging Face의 공개 모델들은 서로 독립적으로 존재하는 것이 아니라 Fine-tuning, Quantization, Merging 등의 transformation을 통해 계속 새로운 모델로 파생되면서 **동적인 Model Supply Chain**을 형성함.

특히 소수의 인기 Base Model이 많은 downstream model의 기반이 되기 때문에 Base Model의:

* 변경
* 삭제
* 취약성
* Safety/Security Risk

가 공급망 전체에 큰 영향을 줄 수 있음.

또한 transformation operation은 단순히 모델의 크기나 성능만 바꾸는 것이 아니라 모델의 **risk profile 자체를 변화시킬 수 있음**.

본 논문은 Model Supply Chain을 다음 네 가지 관점에서 분석함.

### Usage

Model Supply Chain이 실제로 어떠한 dependency 구조를 가지고 있는지 분석함.

### Evolution

모델의 추가·삭제·업데이트에 따라 Supply Chain이 어떻게 변화하는지 분석함.

### Quality

Model Card의 provenance와 dependency information이 얼마나 완전하고 정확한지 분석함.

### Risk

Fine-tuning, Quantization, Merging 과정에서 Safety/Security Risk가 어떻게 변화하는지 분석함.

결과적으로 안전한 Model Supply Chain을 위해서는 다음이 필요함.

* **Maintainer**

  * Model Version과 변경 이력을 명확하게 기록
  * 정확한 provenance 및 dependency 제공

* **Consumer**

  * 사용하는 모델의 위험을 평가
  * 수행한 transformation 및 dependency 기록

* **Platform Designer**

  * Model history, license, dependency, risk를 체계적으로 관리할 수 있는 기능 제공

* **Researcher**

  * 누락된 dependency relation을 복원하는 방법 개발
  * Multi-hop risk propagation 분석

---

# One-Line Summary

> **Hugging Face의 공개 모델들이 Fine-tuning·Quantization·Merging을 통해 형성하는 Model Supply Chain을 Usage, Evolution, Quality, Risk 관점에서 대규모 분석하고, 현재 Model Card 기반 provenance가 불완전하며 transformation 과정에서 모델의 위험 또한 변화할 수 있음을 보인 연구.**
